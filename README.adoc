= FPSOT procurement specification

Rules for the procurement material of FPSOT: the draft clause modules that public bodies paste into their own tenders, and the rules that keep those modules lawful and neutral.
Every module requires conformance to a versioned FPSOT specification and its conformance classes, proven by an open test suite or equivalent evidence.
No module ever requires FPSOT software, and "or equivalent" is always there.
FPSOT takes no contracts and bids on no tender.
Version 0.1 is a draft, and the clause modules are drafts that must not be used in a tender before legal review.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Each requirement has an ID from `PRC-001` to `PRC-052`.
The rules bind two parties: the authors of clause packs, and FPSOT as the publisher.

* Write each module in English and French, with the draft banner, the license line, a drafting note, variants by legal regime and a list of fields (PRC-004 to PRC-016).
* Cite a specification with its exact version and conformance classes, add "or equivalent" each time, and never name a product (PRC-020 to PRC-022).
* Publish a pack for one specification only when an implementation that FPSOT did not make passes its suite, or when two independent integrators can deploy it (PRC-040).
* Keep the public register of results open to any implementer, and never judge a bid (PRC-044 to PRC-046).
* Stay out of every tender, and help buyers only in public (PRC-050 to PRC-052).

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
It shows a buyer how to cite an FPSOT specification in a tender, from the choice of variant to the evaluation of bids.
The draft modules are in `clauses/en/` and `clauses/fr/`.
The continuous integration builds each one as an OpenDocument file and a Word file, in the artifact `clauses` of each run.
In Québec, use the French text.
Read the page `counsel.adoc` with your lawyer first: it lists the legal questions that remain open.
The comparison data in `jurisdictions/` shows how Canada and Québec handle the same topics.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book, published as PDF with each release. The book does not include the clause modules.

| `clauses/`
| The draft clause modules, in `en/` and `fr/`, as Markdown, with `pack.md` and the CC BY 4.0 legal code in `LICENSE`.

| `docs/`
| Guides, in the Antora folder layout.

| `scripts/`
| The check of the clause modules, its tests, and the build of their editable formats.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules.

| `diagrams/`
| PlantUML sources and their rendered SVG files.

| `jurisdictions/`
| Comparison data: how each government handles the same topics.
|===
